G1 v2 — Fast entry-pivot + LTP-tier stop-loss
Deliverable: a full replacement for GEAR 1 (G1).txt. §1–2 explain why we're changing. §3–5 are the new spec. §6 has worked examples including your 10:04/10:19 case. §7–10 are config, invariants, edge cases, rollout.

1. Why we're changing — the 10:04 / 10:19 case
The v1 engine did exactly what v1 was written to do. It just isn't the right thing to do on an option that moves 60% in 15 minutes.

1.1 What actually happened on 2026-10-27
IST	Event	PE 22800
10:01:00	NIFTY touches R3 (22784.30). Bias = CE. Isolated = NIFTY 22800 CE.	—
10:04:00	PE 22800 forms a support pivot (15-bar low). pivot_time = 10:04.	62.75
10:04 → 10:19	Pivot sits in unconfirmed state. Price climbs.	62.75 → 100.55
10:19:00	15-bar confirmation hits. confirmed_time = 10:19. PE side → armed.	100.55
—	v1 entry = close at 10:19 = 100.55. Stop = support = 62.75. Risk = 37.6%.	—
—	v1 fires warning = "stop_too_wide" (max 35%) but the trade still arms.	—
1.2 Why 37.6% is not a "trade"
The stop-loss is 37.6% below the entry. On a 100-rupee option, that is a ~38 rupee loss for a ~10 rupee target (the next resistance was 110.70). Reward:risk was 0.27 : 1. That is a losing trade by construction — the market has to move 4× more in your favour than against you, in the 30-minute window before theta eats the premium.

The old STRATEGY_MAX_STOP_PCT = 0.35 was supposed to prevent this. It didn't, because v1 treats it as a soft warning, not a block. The trade arms, the operator sees a yellow triangle, and the discipline has to come from a human watching a screen. That's not a strategy.

1.3 Three independent root causes
#	Root cause	Effect on 2026-10-27
1	Entry price uses the display confirmed_time (15 bars)	15-minute lag between the pivot forming (10:04) and the entry being priced (10:19). On a fast-moving option that's a 60% drift.
2	Stop = support pivot price, unconditionally	For cheap options, support can be 40%+ below LTP. A "support" stop on a 70-rupee option that bounced from 62.75 is not a stop — it's a hope.
3	STRATEGY_MAX_STOP_PCT is advisory	Fires, logs, does not block. The bad trade proceeds.
All three have to be fixed together. Fixing (1) alone gets you a good entry sometimes, but on a gap day the support can still be far. Fixing (2) alone gives you a good stop but on a bad entry. Fixing (3) alone blocks the 10:04 case entirely — you never trade it, even though a perfectly fine 10:06 entry existed.

2. The two changes in a nutshell
Change A — dual confirmation windows.
Keep left=15 / right=15 for the SR chart, the /isolated SR Tracking card, and the Telegram SR messages. Add a fast scan with left=15 / right=3 that runs only for the entry signal, only after isolation. A support pivot that was a 15-bar low at 10:04 is confirmed for entry purposes at 10:07, not 10:19. Entry price = close at 10:07 ≈ 70. Support structure unchanged.

Change B — LTP-tier stop-loss.
Stop is no longer support_price. Stop is entry_price × (1 − sl_pct) where sl_pct comes from a configurable tier table keyed on entry_price:

LTP bucket	sl_pct
LTP < 100	15%
100 ≤ LTP < 200	12%
200 ≤ LTP ≤ 300	10%
LTP > 300	5%
On the 10:04 pivot: entry ≈ 70 → tier <100 → sl_pct = 15% → stop = 70 × 0.85 = 59.50, risk = 15% — within the 35% hard cap, so it arms cleanly.

Resistance blocker. Kept as-is (no change proposed). It is effectively a no-op today — see §9.1. That is fine for now; it does not affect the new logic.

3. New entry-pivot model (Option A)
3.1 Dual confirmation, one candle series
Every support pivot is tracked with two confirmed-times simultaneously:

Field	Right bars	Used by
confirmed_time	15	Chart, /isolated SR Tracking card, Telegram SR messages, the "pre_isolation / post_isolation" sidecar. Unchanged.
confirmed_time_fast	3	Entry-signal arming, resistance-blocker check, first-to-confirm tiebreak. New.
Both timestamps derive from the same pivot_bar_index and pivot_time. The pivot itself is identical — it must still be a strict 15-bar low (left=15). Only the "when is it tradeable" moment differs.

3.2 The fast scan runs only post-isolation
The left=15 / right=3 scan is not part of the always-on SR engine. It is invoked lazily by strategy_entry_signal_service.compute() only when an isolated instrument exists, and only for the two instruments at the isolated strike (CE and PE).

Pre-isolation: only right=15 runs. No extra CPU.
Post-isolation: right=15 (display) and right=3 (entry) both run for 2 instruments. Cost is negligible.

3.3 Fast scan algorithm
Read the live SR engine's in-memory candle series for the instrument (same source _candle_close_at already uses). Run a strict pivot scan with left=15, right=3:

text
for i in [15, len(candles) − 3):
    c = candles[i]
    support   if  c.low  < candles[j].low   for all j in [i−15, i−1] ∪ [i+1, i+3]
    resistance if  c.high > candles[j].high  for all j in [i−15, i−1] ∪ [i+1, i+3]
The result is a list of {price, pivot_time, pivot_bar_index, confirmed_bar_index, confirmed_time} records — identical shape to the v1 SR levels, except right_bars = 3.

The fast list is not persisted to disk. It is a pure in-memory view for the current poll.

3.4 Fallback when the fast bar is not yet closed
If confirmed_time_fast == now (the confirming bar is still forming), the entry price falls back to the live LTP. The arm still fires (the pivot is confirmed — 3 bars exist), but the price is taken from the tick, not the bar close. Same fallback chain as v1.

4. New stop-loss model (LTP-tier)
4.1 The tier table
entry_price	sl_pct	Example stop
< 100	15%	70 → 59.50
100 – 199.95	12%	150 → 132.00
200 – 300	10%	280 → 252.00
> 300	5%	350 → 332.50
Values are configurable via STRATEGY_ENTRY_STOP_LTP_TIERS (JSON array, see §7). The table above is the default.

4.2 Computation
text
sl_pct   = tier_lookup(entry_price)
sl_pct   = min(sl_pct, STRATEGY_MAX_STOP_PCT)     # hard cap, default 0.35
stop_raw = entry_price × (1 − sl_pct)
stop     = round_down_to_tick(stop_raw)            # see §4.3
stop_pct = (entry_price − stop) / entry_price      # for display / audit
stop_pct is now always ≤ sl_pct by construction. It is no longer an outcome variable the engine "discovers"; it is a parameter of the strategy.

4.3 Tick rounding — round down, not up
round_down_to_tick(stop_raw) — i.e. move the stop further from entry until it lands on a valid tick. Rationale: on a low-priced option (e.g. entry 0.50, tick 0.05, sl_pct=15% → stop_raw = 0.425), rounding up to 0.45 gives a 10% stop (tighter than intended → premature exit); rounding down to 0.40 gives a 20% stop (wider → room to breathe). Round-down matches the operator's intent ("give me ~15% room") and errs on the side of not being whipsawed.

Configurable via STRATEGY_ENTRY_STOP_TICK_ROUNDING = "down" | "up" | "nearest" (default "down").

4.4 Hard cap and fail-safe
If the tier table yields sl_pct > STRATEGY_MAX_STOP_PCT (0.35), that is a configuration error — every default tier is well under 0.35. The engine:

Clamps sl_pct to STRATEGY_MAX_STOP_PCT.

Logs ERROR [strategy-entry] sl_pct <x> exceeds hard cap <y>; clamping. Fix STRATEGY_ENTRY_STOP_LTP_TIERS.

Continues with the clamped value so the trade is not silently dropped.

If entry_price ≤ 0 (bad data, illiquid instrument, dead tick): block the candidate with state_note = "invalid_entry_price".

5. Updated step-by-step logic (full v2 spec)
Only the changed steps are annotated. Everything else is byte-for-byte identical to v1 and reproduced here so the file is self-contained.

Step 1 — Compute OR levels (09:16:10) — unchanged
Same as v1. H, L, A, D_H, D_L, R1, S1, R2, S2, R3, S3, R3_Threshold, S3_Threshold written to data/index/<idx>/first_candle.json.

Step 2 — Filter to a CE/PE strike list — unchanged
Same as v1. ceil(Rx/step) × step for CE, floor(Sx/step) × step for PE, union, range filter, listing resolution. Output level_instruments.json with type on each entry.

Step 3 — Live SR engine accumulates pivots — unchanged
left=15 / right=15 for chart, /isolated SR Tracking, Telegram. Every confirmed pivot written to live_sr_levels.json. This step is untouched by v2.

Step 4 — Watch for R3 / S3 touches — unchanged
Priority NIFTY-R3 → NIFTY-S3 → SENSEX-R3 → SENSEX-S3, throttled to 2 s. First touch isolates, rest log as already_isolated.

Step 5 — Pick the bias-side instrument at touch — unchanged
Bias side fixed by touch (R3→CE, S3→PE). Nearest filtered strike to trigger LTP. SENSEX special case with NIFTY reference / stale-tick fallback. Same as v1.

Step 6 — Snapshot the picked instrument at touch — unchanged
Own LTP, touch-minute OHLC, first-candle OHLC, own OR levels frozen into the isolation record.

Step 7 — Persist the isolation record — unchanged
data/level_isolated_instrument.json. Tracker attached. Telegram "Level Isolation · Instrument Locked".

Step 8 — SR tracker begins watching — unchanged
pre_isolation snapshot, then every new right=15 confirmation as post_isolation, sidecar file, dedup on (level, price, confirmed_time).

Step 9 — Strategy entry signal — CHANGED
Recomputed every 10 s (browser) / 5 min (scheduler). Read:

The isolation record (touch time, bias side).

The fast pivot scan (left=15 / right=3) for both sides at the isolated strike (§3.3).

The fast resistance scan (left=15 / right=3) for the resistance-blocker check.

text
W = [touch_time, touch_time + STRATEGY_ENTRY_BUFFER_MINUTES]   # unchanged, 10 min

for each candidate side (bias + counter when crossover):
    supports_in_window ← fast_supports where pivot_time ∈ W
    sort by pivot_time ascending

    for each support S (earliest first):
        # Resistance-blocker — unchanged rule, evaluated on the fast window
        blocker ← first R such that
                    R.pivot_time > S.pivot_time
                  AND R.price      > S.price
                  AND R.confirmed_time_fast ≤ S.confirmed_time_fast
        if blocker: skip S, try next

        # Arm / waiting gate — based on fast confirmation
        if S.confirmed_time_fast > now:
            state = waiting_confirmation
            return
        else:
            state = armed
            entry_price, source = price_at(S.confirmed_time_fast)   # close, else LTP

            # NEW: structural sanity blocks (all hard-blocks)
            if entry_price is None:            → blocked "no_entry_price"
            if entry_price <= 0:               → blocked "invalid_entry_price"
            if entry_price < S.price:          → blocked "entry_below_support"

            # NEW: LTP-tier stop
            sl_pct   = tier(entry_price)
            sl_pct   = min(sl_pct, STRATEGY_MAX_STOP_PCT)
            stop_raw = entry_price × (1 − sl_pct)
            stop     = round_tick(stop_raw)
            stop_pct = (entry_price − stop) / entry_price

            # NEW: informational warnings (do not block)
            warning = None
            if (entry_price − S.price) / entry_price > 0.20:
                warning = "support_far_below_entry"

            # Target — unchanged rule (next resistance above entry)
            target = nearest resistance above entry_price

            entry = {
                price:        entry_price,
                price_source: "candle_close_at_confirmed_fast" | "live_ltp",
                time:         S.confirmed_time_fast,
                stop:         stop,
                stop_pct:     stop_pct,
                sl_pct:       sl_pct,
                stop_source:  "ltp_tier",
                target:       target,
                target_pivot_time: …,
            }
            return

    state = blocked "all_supports_in_window_blocked"
Tiebreak (both sides armed):

text
sort armed candidates by confirmed_time_fast ascending
earliest wins → chosen
other → discarded, note = "first_to_confirm_won_by_other_side"
The tiebreak now uses confirmed_time_fast, not confirmed_time, so the winner is decided at the fast-confirmation moment, consistent with the entry.

6. Worked examples
6.1 Your 10:04 case (LTP < 100, fast confirmation wins)
Inputs: touch 10:01 (NIFTY R3, PE bias). PE 22800 support pivot: price 62.75, pivot_time = 10:04:00.

v1	v2
confirmed_time_fast	—	10:07:00
confirmed_time (display)	10:19:00	10:19:00 (unchanged)
Entry price	100.55 (close at 10:19)	≈ 70 (close at 10:07)
sl_pct (tier)	— (used support)	70 < 100 → 15%
Stop	62.75 (support)	70 × 0.85 = 59.50
Stop distance	37.6%	15.0%
Target	110.70	110.70
Reward : Risk	10.15 : 37.80 = 0.27	40.70 : 10.50 = 3.88
Hard warning	stop_too_wide (advisory)	— (within cap, no warning)
Armed?	Yes	Yes
Tradeable?	No (0.27 R:R, 38% risk)	Yes (3.88 R:R, 15% risk)
Entry price is approximate — the actual 10:07 close depends on the tick path — but the structure is deterministic: the entry is at the 3-bar confirmation, not the 15-bar one, and the stop is 15% below that, not at the support.

6.2 Mid-tier (100 ≤ LTP < 200)
Entry 150, support 130.

sl_pct = 12% → stop = 132, risk = 12%, reward (target 175) : risk = 25 : 18 = 1.39 : 1. Arms.

If support is 130, the stop (132) is above the support. That means the pct-stop fires before the support breaks. Operator sees support_far_below_entry (gap = (150−130)/150 = 13.3% — under the 20% warning threshold, so no warning). Fine.

6.3 Upper-tier (200 ≤ LTP ≤ 300)
Entry 280, support 240.

sl_pct = 10% → stop = 252, risk = 10%. Target 320 → reward 40 : risk 28 = 1.43 : 1. Arms.

Support gap (280−240)/280 = 14.3% → no warning.

6.4 Above-tier (LTP > 300)
Entry 350, support 300.

sl_pct = 5% → stop = 332.50, risk = 5%. Target 380 → reward 30 : risk 17.5 = 1.71 : 1. Arms.

This tier exists because 350+ rupee options have enough premium that a 5% move is already a meaningful loss; wider stops there are usually overkill.

6.5 Very low LTP edge (< 20)
Entry 15, tick 0.05.

sl_pct = 15% → stop_raw = 12.75 → round_down → 12.75 (already on tick). Risk = 15%. Arms.

Entry 5: stop_raw = 4.25, tick 0.05 → 4.25 is valid. Risk = 15%. Arms, but note: at 5 rupees, 15% = 0.75 rupees = 15 ticks, which is one bar of noise on a PE that moves 20 ticks a minute. Operator should size down or skip. This is a note, not a block — the tier is the same, the operator owns the sizing.

Entry 0.50: stop_raw = 0.425 → round_down → 0.40 (20% stop). Slightly wider than the 15% requested; that is the tick-rounding behaviour. Acceptable.

Entry ≤ 0: block invalid_entry_price.

6.6 Block case — entry below support
Entry 62.75 (fast close went below the support), support 62.75. entry < support → blocked "entry_below_support". This is the "support didn't hold" case the pct-stop cannot save you from. New hard block (v1 had this as a soft price_at_or_below_support warning).

9. Notes and edge cases
9.1 The resistance blocker is currently a no-op
The v1 rule is:

R blocks S iff R.pivot_time > S.pivot_time AND R.price > S.price AND R.confirmed_time ≤ S.confirmed_time.

If both R and S use the same confirmation lag (15 bars in v1, 3 bars in v2), then R.pivot_time > S.pivot_time implies R.confirmed_time > S.confirmed_time. The third clause is therefore always false, and the blocker never fires. It is dead code today.

We are keeping the code path unchanged for v2 — it does not affect the 10:04 case, and removing it would be a behaviour change we don't need to make right now. If you ever want a real resistance check, the correct direction is the opposite: R.pivot_time < S.pivot_time (R formed before S, S coiled under it, and R was confirmed by the time S confirms) → block. That is a v3 change; note it, don't action it.

The user's hunch ("not resistance not about to create") is best served by the fast window: any resistance that forms at 10:05 or later cannot be confirmed (even fast) by 10:07, so it cannot block. The fast window already gives you what you want.

9.2 New hard blocks
The v2 entry block has three hard blocks:

state_note	Condition	Rationale
invalid_entry_price	entry_price ≤ 0	Bad tick / no candle.
no_entry_price	Both candle close and live LTP missing	Feed down.
entry_below_support	entry_price < S.price	Price broke support before confirmation; the pivot is not the floor any more. Was a soft warning in v1; promoted to block in v2.
9.3 Fast bar not closed yet
When confirmed_time_fast == now (the 3rd bar is still forming), entry_price falls back to live LTP. The entry block carries price_source = "live_ltp" so the operator can see the difference. The stop is still computed from the LTP: stop = ltp × (1 − sl_pct). This is consistent — the stop is "X% below whatever I paid", not "X% below the fast close".

9.4 Multiple fast-confirmed supports
Iterate by pivot_time ascending (same as v1). First non-blocked wins. Remaining supports are not re-tried. This is intentional — a second pivot 5 minutes later would be a different setup, and re-arming on it would violate STRATEGY_ENTRY_ONLY_ONCE_PER_DAY = true.

9.5 Backward compatibility with v1 records
A v1 level_isolated_instrument.json on disk has no confirmed_time_fast field in its entry_support block. On the first poll after upgrade:

The entry signal recomputes from scratch (it always does). It re-reads the candle series, runs the fast scan, and produces a fresh entry block. It does not read the persisted confirmed_time_fast from any sidecar.

Therefore no migration is needed for the entry block. The sidecar (level_isolated_instrument_sr.json) is unchanged — it stores the 15-bar confirmed_time only.

level_isolated_instrument_promotion.json from a v1 run has an evidence.entry_support_confirmed_time field with the 15-bar value. On upgrade, that field keeps its v1 meaning (display confirmation) — it is not recomputed. No file rewrite. The promotion is "already applied today", so the operator sees the v1 promotion and the v2 entry block on the same page. That's fine — the promotion was a historical fact.

On the next day, everything is clean.

9.6 Tick granularity on low LTP
Entry 0.50, sl_pct = 15%, stop_raw = 0.425, tick 0.05 → round_down = 0.40 → actual risk 20%. The stop is wider than the tier requested. This is documented behaviour (§4.3). If you want strict tier adherence, set STRATEGY_ENTRY_STOP_TICK_ROUNDING = "nearest" and accept that some stops land at 0.45 (tighter than 15%, premature exit risk).

9.7 The "very low LTP" note
At LTP < 20, a 15% stop is 3 ticks or less. That is bar noise on most days. The engine will still arm (as configured), but the operator should consider STRATEGY_ENTRY_STOP_LTP_TIERS with an extra {"max_ltp": 20, "sl_pct": 0.20} tier. This is a configuration change, not a code change — the parser already supports arbitrary tier counts.

Next trading day: everything is clean. The first support pivot on the isolated strike will arm at pivot_time + 3 min, with the tier-based stop.
