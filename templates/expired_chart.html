LWC "Value is null" fix (2026-10-28) ------------------------------------ The Upstox expired-candles endpoint returns candles in DESCENDING order (newest-first). Lightweight Charts requires ASCENDING order; feeding descending data into `setData()` does not throw at the call site but poisons the internal series index. Every subsequent chart render (updateAllViews) then throws `Value is null`. The fix (layered, belt-and-suspenders): 1. Backend (`routes/expired_chart_routes.py`) sorts candles ascending before returning. 2. Frontend (`fetchCandlesFromApi`) re-sorts ascending and de-dupes by `time` — protects against any future backend regression or a direct JSON paste. 3. Every line series uses `setLineDataSafe()`, which filters non-finite values, de-dupes, sorts, and REMOVES the series if it cannot produce a valid >=2-point line. This prevents an empty/partial line from leaking into a render pass. 4. `applyMarkersToCandleSeries` detaches any previous marker primitive before attaching a new one (v5 primitives stack otherwise) and filters markers with invalid times. No live WebSocket feed. No debounced live search bar. All other indicators (EMA, SR pivots with configurable L/R, SR labels), SR params card, instrument info card, price-scale controls, scroll nav, and the CE↔PE swap FAB are preserved. #} {% extends "base.html" %} {% block title %}{{ instrument_key or 'Expired / Active Chart' }} - Trading Dashboard{% endblock %} {% block head %} {% endblock %} {% block content %}
