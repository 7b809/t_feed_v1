## 1. Executive Summary & Core Architectural Premise

The cross-index relational foundation remains intact: any of the four monitored benchmark indices touching $R3$ or $S3$ establishes the session bias ($R3 \rightarrow \text{CE}$, $S3 \rightarrow \text{PE}$). The execution destination maps to the nearest round-50 NIFTY 50 strike based on spot LTP at the trigger millisecond.

v4.2 refines **Path B (External-Index Trigger)** in three operational areas:

1. **Opening Range Entry Gate:** Entry is gated by the execution instrument's own first-candle range. The engine will not buy an option whose premium has broken out beyond the day's initial balance area $[L, H]$ at the moment of SR confirmation, preventing extended chases.
2. **SR-Ladder Trailing & Breakeven Lock:** The fixed target no longer terminates the position. Instead, the target and the option's own OR resistance ladder ($R1 \rightarrow R2 \rightarrow R3\_Threshold \rightarrow R3$) act as progressive rungs. Crossing each rung ratchets the stop-loss up to the previous rung.
3. **Monotonic Capital Protection:** Crossing the first rung above entry permanently anchors the stop-loss at entry price ($\text{SL} \ge \text{entry}$), ensuring a profitable move cannot reverse into a loss.

## 4. Step 9B: Path B (External Trigger) — Entry Gate Added

### 4.1 Monitored Instrument
Only the bias-side instrument (`isolation_record.primary_key`) is monitored for post-isolation SR confirmations. The counter instrument serves strictly as an execution destination.

### 4.2 Level Eligibility Matrix
A pivot level $L$ is valid for order evaluation if and only if:
1. $L.\text{confirmed\_time\_fast} > \text{isolation\_record.touched\_at}$ (strictly post-isolation).
2. $L.\text{left\_bars} \ge \text{STRATEGY\_ENTRY\_PIVOT\_LEFT\_BARS}$ and $L.\text{right\_bars} \le \text{STRATEGY\_ENTRY\_PIVOT\_RIGHT\_BARS}$.
3. Deduplication key `(bias_instrument_key, L.type, round(L.price, 4), L.confirmed_time_fast)` is not in `placed_keys`.
4. `strategy_locked_today == False`.
5. Valid ISO-8601 timestamp.

### 4.3 Routing Matrix
| Level Confirmed on Bias Side | Execution Target | Order Side |
| :--- | :--- | :---: |
| **Support** | Bias-side instrument (`primary_key`) | BUY |
| **Resistance** | Counter-side instrument (`opposite_key`) | BUY |

### 4.4 First-Candle Range Entry Gate (v4.2 New)
Before arming an order on `target_key`, the engine evaluates the execution instrument's own opening bar:

```python
fc = first_candle_for(target_key)  # 09:15 candle (or first available of day)
if fc is None:
    placed_keys.add(dedup)
    return {"status": "skipped", "reason": "no_first_candle"}

if not (fc["L"] <= entry_price <= fc["H"]):
    placed_keys.add(dedup)
    return {
        "status": "skipped",
        "reason": "outside_first_candle_range",
        "entry_price": entry_price,
        "first_candle_high": fc["H"],
        "first_candle_low": fc["L"]
    }
```

#### Gate Principles:
* **Target-Centric:** Evaluates against the first candle of the *execution contract*, not the bias contract.
* **Fair Value Anchor:** Buying above $H$ chases overextended premium; buying below $L$ indicates decaying momentum.
* **Telemetry & Dedup:** Skipped levels are added to `placed_keys` to prevent re-firing on duplicate evaluations, but they **do not** trigger `strategy_locked_today`.

## 5. Step 10B: SR-Ladder Profit Trail & Breakeven Lock

### 5.1 Profit Calculation
$$\text{Profit}_{\text{₹}} = (\text{Current LTP} - \text{Entry Price}) \times \text{Lot Size}$$

### 5.2 Opening Range Formulas & Ladder Construction
Opening Range values are computed from the execution contract's first candle:

$$A = \frac{H + L}{2}, \quad D_H = H - A, \quad D_L = A - L$$

$$R1 = A + 0.5 D_H, \quad R2 = A + 2.0 D_H, \quad R3T = A + 2.5 D_H, \quad R3 = A + 3.0 D_H$$

$$S1 = A - 0.5 D_L, \quad S2 = A - 2.0 D_L, \quad S3T = A - 2.5 D_L, \quad S3 = A - 3.0 D_L$$

#### Ladder Assembly Algorithm:
```python
def build_ladder(target_key, fc, entry_price, target_price):
    A = (fc["H"] + fc["L"]) / 2.0
    D_H = fc["H"] - A
    raw = {
        "T": target_price,
        "R1": A + 0.5 * D_H,
        "R2": A + 2.0 * D_H,
        "R3T": A + 2.5 * D_H,
        "R3": A + 3.0 * D_H,
    }
    if STRATEGY_EXT_LADDER_INCLUDE_UNDERLYING_OR:
        raw.update(underlying_rungs_for(target_key))

    rungs, seen = [], set()
    for name, price in sorted(raw.items(), key=lambda kv: (kv[1] or 1e18)):
        if price is None or price <= entry_price + 0.05:
            continue
        key = round(price, 2)
        if key in seen:
            continue
        seen.add(key)
        rungs.append({
            "name": name,
            "price": key,
            "promote_sl_to": None,
            "state_on_cross": None,
        })

    for i, r in enumerate(rungs):
        r["promote_sl_to"] = entry_price if i == 0 else rungs[i - 1]["price"]
        r["state_on_cross"] = "BREAKEVEN_LOCK" if i == 0 else f"LADDER_{i + 1}"

    return rungs
```

> **The "No-Loss" Invariant:** Because `rungs[0].promote_sl_to == entry_price`, crossing the first rung permanently locks the stop-loss at entry. The trade can never result in a negative P&L after rung 0 is reached.

### 5.3 Live Tick Handler & Ratchet Logic

```python
def process_path_b_on_tick(order, current_ltp, held_candles, nifty_ltp):
    if order["status"] != "OPEN":
        return

    lot = order["lot_size"]
    profit_rs = (current_ltp - order["entry_price"]) * lot
    order["peak_profit_rs"] = max(order["peak_profit_rs"], profit_rs)

    # 1. Ladder Ratchet (Strictly Monotonic)
    while order["ladder_index"] < len(order["ladder"]):
        rung = order["ladder"][order["ladder_index"]]
        if current_ltp < rung["price"]:
            break
        order["current_stop"] = max(order["current_stop"], rung["promote_sl_to"])
        order["trail_state"] = rung["state_on_cross"]
        order["ladder_index"] += 1
        if rung["name"] == "T":
            set_strategy_lockdown()  # Halts new order evaluation

    # 2. Optional Rupee Trail Floor (Secondary)
    if STRATEGY_EXT_RUPEE_TRAIL_ENABLED:
        if order["peak_profit_rs"] >= STRATEGY_EXT_PROFIT_ACTIVATION_RS:
            lock_rs = max(
                STRATEGY_EXT_TRAIL_FLOOR_RS,
                order["peak_profit_rs"] - STRATEGY_EXT_TRAIL_GAP_RS
            )
            rupee_sl = round_down_tick(order["entry_price"] + lock_rs / lot, 0.05)
            order["current_stop"] = max(order["current_stop"], rupee_sl)
            if order["trail_state"] == "PRE_TRAIL":
                order["trail_state"] = "TRAILING"

    # 3. Exit Evaluations
    if order["current_stop"] > order["initial_stop"] and current_ltp <= order["current_stop"]:
        reason = "LADDER_STOP_HIT" if order["ladder_index"] > 0 else "TRAILING_STOP_HIT"
        close_order(order, reason, order["current_stop"])
        return

    if order["trail_state"] != "PRE_TRAIL":
        if STRATEGY_EXT_BEARISH_EXIT_ENABLED and is_bearish_regime(
            order["instrument_key"], held_candles, nifty_ltp
        ):
            close_order(order, "BEARISH_EXIT", current_ltp)
            return
    else:
        if current_ltp <= order["initial_stop"]:
            close_order(order, "STOP_HIT", order["initial_stop"])
            return

    if now_ist().time() >= time(15, 30):
        close_order(order, "EOD_EXIT", current_ltp)
        return
```

### 5.4 Exit Priority Matrix (v4.2)

| Priority | Trigger | Exit Price | Action / Consequence |
| :---: | :--- | :--- | :--- |
| **1** | $\text{LTP} \le \text{current\_stop}$ (where $\text{current\_stop} > \text{initial\_stop}$) | `current_stop` | Closes position (`LADDER_STOP_HIT`). |
| **2** | Bearish regime confirmed (only when `trail_state != PRE_TRAIL`) | Current LTP | Closes position (`BEARISH_EXIT`). |
| **3** | $\text{LTP} \le \text{initial\_stop}$ (while in `PRE_TRAIL`) | `initial_stop` | Closes position (`STOP_HIT`). |
| **4** | EOD ($\ge \text{15:30 IST}$) | Final bar close | Closes position (`EOD_EXIT`). |
| **—** | **Target reached** | *No exit* | $\text{SL} \rightarrow \text{Entry}$; locks new order entries (`strategy_locked_today = True`). Position continues trailing. |

### 5.5 Bearish-Regime Detection
Evaluates to `True` when at least 2 of the 3 conditions hold during trail mode:
1. Last $N$ ($N=2$) completed 1-minute bars on the contract are bearish ($\text{Close} < \text{Open}$).
2. NIFTY 50 Spot LTP drops below the price level confirmed at the last primary support.
3. NIFTY 50 Spot prints $N$ ($N=2$) consecutive lower closes on the 1-minute timeframe.

### 5.6 Lockdown Behavior
When a Path B order crosses its target rung:
* `strategy_locked_today` is set to `True`.
* No further SR levels are armed for the day.
* All open positions remain active, laddering upwards until hit by their trailing stop or EOD.
* Configurable via `STRATEGY_EXT_LOCKDOWN_ON`: `target` (default), `r3_threshold`, `r3`, `none`.

## 10. Backward Compatibility & Edge Handling

* **Legacy Order Objects:** Records missing `ladder`, `current_stop`, or `initial_stop` default to `trail_state = "PRE_TRAIL"` with `current_stop = stop_loss` and an empty ladder, continuing their fixed SL/Target lifecycle until closed.
* **Path A Unaltered:** Path A retains its 10-minute scan, auto-reversal, single-trade promotion, and fixed target exits. The ladder engine and opening range gate do not evaluate Path A.
* **Multi-Rung Fast Breakouts:** If a 1-second surge gaps through multiple rungs, the `while` loop sequentially verifies each rung and ratchets `current_stop` directly to the highest qualified level.
* **Monotonic Floor:** Trailing stops never decrease, even if spot or premium plunges within the same 1-minute candle.
