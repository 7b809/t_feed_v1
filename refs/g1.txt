## 1. Executive Summary & Core Architectural Premise

### 1.1 The Cross-Index Relational Concept
The G1 v4.0 architecture leverages **cross-index lead-lag dynamics** across key benchmark and high-beta indices in the Indian markets (`MIDCPNIFTY`, `BANKNIFTY`, `NIFTY`, `SENSEX`).

* When a leading or high-momentum index (such as **MIDCPNIFTY** or **BANKNIFTY**) breaks or touches its daily extreme opening boundaries ($R3$ or $S3$), it dictates the **directional bias for the broader market**.
* Regardless of which index touches its boundary first, **all derivative order executions are strictly isolated into NIFTY 50 options** for superior liquidity, minimal spread variance, and tight tick-level fills.
* Once the NIFTY option strike is relationally isolated, a dedicated **10-minute scan window** monitors fast pivot formation using a **`left=15, right=3`** bar structure:
  * **Support Confirmed ($S$):** Indicates strength/continuation. Execute BUY on the **isolated instrument itself**.
  * **Resistance Confirmed ($R$):** Indicates rejection/exhaustion. Execute BUY on the **opposite instrument** (Auto-Reverse).

## 2. Multi-Index Priority Arbitration & Relational Mapping

### 2.1 Index Universe & Polling Configuration
The engine subscribes to 2-second WebSocket or snapshot tick feeds for four primary indices:

| Index Symbol | Instrument Key | Exchange | Segment | Priority Rank | Strike Step |
| :--- | :--- | :--- | :--- | :---: | :---: |
| `MIDCPNIFTY` | `NSE_INDEX\|NIFTY MID SELECT` | NSE | `NSE_INDEX` | **1** | 25 |
| `BANKNIFTY` | `NSE_INDEX\|Nifty Bank` | NSE | `NSE_INDEX` | **2** | 100 |
| `NIFTY` | `NSE_INDEX\|Nifty 50` | NSE | `NSE_INDEX` | **3** | 50 |
| `SENSEX` | `BSE_INDEX\|SENSEX` | BSE | `BSE_INDEX` | **4** | 100 |

### 2.2 Relational Isolation Rules
1. **Trigger Condition:** The first index to touch either its pre-calculated $R3$ (ceiling) or $S3$ (floor) boundary wins the isolation event.
2. **Tie-Break Matrix:** If multiple indices cross their boundary within the exact same 2-second polling batch:
   $$\text{MIDCPNIFTY} \succ \text{BANKNIFTY} \succ \text{NIFTY} \succ \text{SENSEX}$$
3. **Cross-Index Isolation Logic:**
   * **If $R3$ Touched (by MIDCPNIFTY or any priority index):**
     * **Primary Isolated Instrument:** `NIFTY <Strike> CE`
     * **Opposite (Counter) Instrument:** `NIFTY <Strike> PE`
   * **If $S3$ Touched (by MIDCPNIFTY or any priority index):**
     * **Primary Isolated Instrument:** `NIFTY <Strike> PE`
     * **Opposite (Counter) Instrument:** `NIFTY <Strike> CE`
4. **NIFTY Strike Strike Selection Formula:**
   $$\text{NIFTY Strike} = \text{round}\left(\frac{\text{Current NIFTY Spot LTP}}{50}\right) \times 50$$
5. **Session Lock:** Once an isolation occurs, the system locks state (`is_already_isolated = True`). No subsequent touches on any index can trigger a new isolation for the day.

## 3. End-to-End Execution Pipeline (Steps 1 to 11)

### Step 1: Pre-Market Opening Range Formulation (09:16:10 AM)
Calculate $H, L, A, R1, S1, R2, S2, R3, S3$ for `MIDCPNIFTY`, `BANKNIFTY`, `NIFTY`, and `SENSEX`. Store calculations in `data/index/<symbol>/first_candle.json`.

### Step 2: Strike Universe Preparation (09:16:15 AM)
Fetch active option chain contracts for NIFTY 50 weekly expiry and map valid strike identifiers.

### Step 3: Background Structural Scanner
Continuously calculate standard pivot levels (`left=15, right=15`) across all monitored underlying assets for telemetry and dashboard monitoring.

### Step 4: Multi-Index Boundary Watch (09:16:15 – 15:30:00)
Poll tick prices every 2 seconds. Check boundary breaches:
```python
touches = []
for idx in [MIDCPNIFTY, BANKNIFTY, NIFTY, SENSEX]:
    if idx.ltp >= idx.R3:
        touches.append({"index": idx.symbol, "boundary": "R3", "bias": "CE", "priority": idx.priority})
    elif idx.ltp <= idx.S3:
        touches.append({"index": idx.symbol, "boundary": "S3", "bias": "PE", "priority": idx.priority})

if touches and not is_already_isolated():
    touches.sort(key=lambda x: x["priority"])
    winning_event = touches[0]
    isolate_nifty_relationally(winning_event)
```

### Step 5: NIFTY Relational Strike Isolation & Counter Assignment
* Fetch the exact current `NIFTY 50` Spot LTP at the trigger millisecond.
* Compute the nearest round ATM strike ($\text{step} = 50$).
* **Primary (Isolated) Instrument:**
  * If winning event was $R3 \implies \text{Primary} = \text{NIFTY ATM CE}$
  * If winning event was $S3 \implies \text{Primary} = \text{NIFTY ATM PE}$
* **Opposite (Counter) Instrument:**
  * If Primary is $\text{CE} \implies \text{Opposite} = \text{NIFTY ATM PE}$
  * If Primary is $\text{PE} \implies \text{Opposite} = \text{NIFTY ATM CE}$

### Step 6 & 7: Persistence & Alerting
Write the isolation details to `data/level_isolated_instrument.json` and dispatch a notification to Telegram:
`[Isolation Event] Triggered by MIDCPNIFTY R3. Isolated: NIFTY 24800 CE | Counter: NIFTY 24800 PE`.

### Step 8: Initialize 10-Minute Fast Scan Window
Open a 10-minute surveillance window:
$$W = [T_{\text{touch}},\ T_{\text{touch}} + 10\text{ minutes}]$$

### Step 9: Fast Pivot Scan (`left=15, right=3`) & Trade Decision Matrix
On every 1-minute candle close inside window $W$, scan the **Primary Isolated Instrument** using `left=15, right=3`:

* **Case 1: Fast Support ($S$) Confirmed on Primary Instrument:**
  * **Action:** BUY the **Primary Isolated Instrument**.
  * **Order Type:** Continuation / Bounce.
  * **Entry Price:** Candle Close of confirmation bar or Live LTP.
* **Case 2: Fast Resistance ($R$) Confirmed on Primary Instrument (Support Absent):**
  * **Action:** BUY the **Opposite (Counter) Instrument**.
  * **Order Type:** Reversal on Exhaustion.
  * **Entry Price:** Live LTP of the Counter Instrument at the exact confirmation second of $R$.
* **Case 3: Both $S$ and $R$ form within window:**
  * Support takes priority ($S$ wins). BUY the **Primary Isolated Instrument**.
* **Case 4: Window $W$ expires without valid $S$ or $R$ confirmation:**
  * Mark state as `blocked: window_expired_no_pivot`. Hard halt for the session.

### Step 10: Strategy Promotion & State Lockdown
Record promotion details to `data/level_isolated_instrument_promotion.json` and block any further strategy executions for the trading day.

### Step 11: LTP-Tier Stop-Loss & Order Transmission
Determine Stop-Loss according to the LTP bracket and transmit order to broker endpoint:
$$\text{Stop} = \text{round\_down\_0.05}(\text{Entry LTP} \times (1 - \text{Tier SL \%}))$$

## 4. Complete Pivot Scan & Execution Decision Logic

```python
def process_step_9_decision_logic(isolation_record, primary_candles, counter_candles):
    """
    Evaluates fast pivot formation on the Primary Isolated Instrument.
    Applies the left=15, right=3 logic to trigger either same-instrument 
    or opposite-instrument order execution.
    """
    touch_time = isolation_record.touch_time
    window_end = touch_time + timedelta(minutes=10)
    current_time = get_market_time()

    # Fast Pivot Scan on Primary Isolated Instrument (left=15, right=3)
    fast_supports = scan_pivots(primary_candles, left=15, right=3, kind="SUPPORT", window=(touch_time, window_end))
    fast_resistances = scan_pivots(primary_candles, left=15, right=3, kind="RESISTANCE", window=(touch_time, window_end))

    # -------------------------------------------------------------------------
    # RULE 1: SUPPORT CONFIRMED ON PRIMARY INSTRUMENT (Priority)
    # -------------------------------------------------------------------------
    if len(fast_supports) > 0:
        S = fast_supports[0]
        if S.confirmed_time > current_time:
            return {"status": "WAITING_BAR_COMPLETION", "target": isolation_record.primary_symbol}

        # Place order on the isolated instrument itself
        entry_price = get_candle_close(primary_candles, S.confirmed_time) or get_live_ltp(isolation_record.primary_key)
        
        # Invalidation check: Price collapsed below support level
        if entry_price < S.price:
            return {"status": "BLOCKED", "reason": "entry_price_below_support_floor"}

        stop_loss, sl_pct = calculate_ltp_tier_stop(entry_price)
        target_price = locate_next_resistance(primary_candles, entry_price)

        return {
            "status": "ARMED",
            "action": "BUY",
            "execution_target": "SAME_INSTRUMENT",
            "instrument_key": isolation_record.primary_key,
            "symbol": isolation_record.primary_symbol,
            "entry_type": "PRIMARY_SUPPORT_CONFIRMED",
            "entry_price": entry_price,
            "stop_loss": stop_loss,
            "sl_pct": sl_pct,
            "target": target_price,
            "pivot_details": {"type": "SUPPORT", "price": S.price, "time": S.pivot_time}
        }

    # -------------------------------------------------------------------------
    # RULE 2: RESISTANCE CONFIRMED ON PRIMARY INSTRUMENT -> ENTER OPPOSITE
    # -------------------------------------------------------------------------
    elif len(fast_resistances) > 0 and len(fast_supports) == 0:
        R = fast_resistances[0]
        if R.confirmed_time > current_time:
            return {"status": "WAITING_BAR_COMPLETION", "target": isolation_record.opposite_symbol}

        # Resistance hit on primary -> Place order on opposite instrument
        counter_key = isolation_record.opposite_key
        counter_symbol = isolation_record.opposite_symbol
        counter_entry_price = get_live_ltp(counter_key)

        if not counter_entry_price or counter_entry_price <= 0:
            return {"status": "BLOCKED", "reason": "invalid_counter_instrument_ltp"}

        stop_loss, sl_pct = calculate_ltp_tier_stop(counter_entry_price)
        target_price = locate_next_resistance(counter_candles, counter_entry_price)

        return {
            "status": "ARMED",
            "action": "BUY",
            "execution_target": "OPPOSITE_INSTRUMENT",
            "instrument_key": counter_key,
            "symbol": counter_symbol,
            "entry_type": "REVERSAL_ON_PRIMARY_RESISTANCE",
            "entry_price": counter_entry_price,
            "stop_loss": stop_loss,
            "sl_pct": sl_pct,
            "target": target_price,
            "reversal_trigger": {"primary_resistance_price": R.price, "pivot_time": R.pivot_time}
        }

    # -------------------------------------------------------------------------
    # RULE 3: WINDOW EXPIRATION TIMEOUT
    # -------------------------------------------------------------------------
    if current_time > window_end:
        return {"status": "BLOCKED", "reason": "ten_minute_window_expired_no_formation"}

    return {"status": "SCANNING", "reason": "awaiting_left15_right3_formation"}
```

## 5. LTP-Tier Stop-Loss Bracket Structure

The system uses fixed percentage brackets based on the trade's entry premium price:

$$\text{Stop Price} = \lfloor \text{Entry Price} \times (1 - \text{SL \%}) \rfloor_{0.05}$$

| Entry Premium LTP Bracket | SL % | Dummy Entry LTP | Calculated Stop Price | Risk per Lot (50 Qty) |
| :--- | :---: | :---: | :---: | :---: |
| **$\text{LTP} < ₹100$** | **15%** | ₹82.00 | ₹69.70 | ₹615.00 |
| **$₹100 \le \text{LTP} < ₹200$** | **12%** | ₹145.00 | ₹127.60 | ₹870.00 |
| **$₹200 \le \text{LTP} \le ₹300$** | **10%** | ₹240.00 | ₹216.00 | ₹1,200.00 |
| **$\text{LTP} > ₹300$** | **5%** | ₹380.00 | ₹361.00 | ₹950.00 |

*Maximum Risk Cap Guard:* In all instances, if calculated loss exceeds 35%, `STRATEGY_MAX_STOP_PCT = 0.35` clamps the stop distance.
